# Glycan Flow Simulator — 数理計算検証用プロトタイプ

このフォルダは、公開Webサイトに組み込む前に、Forward（最大フロー＋4配分法）とInverse（容量調整）が研究の制約に従うかを**簡単なネットワーク**で検証するためのものです。GitHub Pages のWeb画面は**まだ変更しません**。

## 内容

- `model.py` — 小規模ネットワーク定義、最大フロー、UQ/CWQ/SU/LCRQ、Inverse容量補正
- `run_validation.py` — 一括計算と結果の書き出し
- `demo_results.json` — 将来のWeb移植時の回帰テストデータ
- `topology.json` — 先輩のデモと整合した簡単なネットワークの構造・基準容量
- `MATH_SPEC.md` — 研究数式との対応を明記した計算仕様
- `VALIDATION_REPORT.md` — 数値結果の解釈と注意点
- `tests/test_model.py` — 容量・流量保存・4手法・Inverse補正の自動テスト

## 実行方法

Python 3.11+ を用意し、次を実行してください。

```bash
python -m pip install -r requirements.txt
python run_validation.py
python -m pytest -q
```

## 研究との対応

- Forward：1段階目でネットワークの最大フロー値を計算。2段階目で**最大フロー値を固定**し、UQ / CWQ / SU / LCRQ の二次目的関数を最小化します。
- Inverse：終端分布の目標値を満たすよう、元の容量からの相対変更量の二乗和を最小化します。終端分布、流量保存、補正容量の非負性、および最大フロー値の維持を検証します。
- **Inverseの解とForwardの4手法は異なる最適化問題です。** Inverseの補正容量から、4つのForward手法すべてが観測分布を出すとは限りません。

## この実装の前提・限界

1. ネットワークは、先輩のWebデモを参考にした**説明用の10ノード・13反応エッジ**です。入力・終端の人工ノードとエッジを追加しています。実際の糖鎖のKEGG IDではありません。
2. 反応容量はデモ用の人工値（元サイトのbase設定に対応）であり、実際のRNA発現量やTPMではありません。固定観測分布 A 25%、B 20%、C 55% も**合成データ**です。決して実測値と表示しないでください。
3. Forwardでエッジ容量を変更する際は各エッジの基準容量の0～200%とします。供給用の人工エッジ（容量120）は固定します。
4. Inverseは基準容量から計算する固定デモです。最大流量120の基準ネットワークに対し、source側カット `{s}` の容量120が不変であるため、新しい容量でも最大流量120が保証されます。これは、論文の固定ベースライン最小カット証明の特殊例です。
5. Inverseの論文式では `F >= F_base` と固定最小カット容量 `F` を同時に課しています。このデモでは固定されたソース供給エッジによって **F=F_base=120** になる設計です。任意のネットワークを扱う汎用Inverse実装ではありません。
6. 数値最適化は、環境にCVXPYがないためSciPy SLSQPを使っています。今回の制約チェックと分析的な下限によるInverse最適値確認を行いますが、元論文で用いたソルバーとの独立した数値比較は**未実施**です。
7. ブラウザ用のJavaScript実装はありません。今後作成する際は、この計算結果を回帰テストの正解データとして利用します。
