# 数理計算仕様（Web移植のための要点）

## Forward

入力：有向グラフ `G=(V,E)`、各エッジの非負容量 `c_e`。出力：最大流量 `F*`、各エッジの流量 `f_e`、3種類の終端分布 `p_i`。

**第1段階：最大流**

- `max Σ_{(s,j)∈E} f_sj`
- `0 ≤ f_e ≤ c_e`
- 中間ノードで `Σ入力流量 = Σ出力流量`

**第2段階：配分最適化**

第1段階の `F*` を固定して、次の目的関数のうち1つを最小化する。

- **UQ**: `Σ_{e∈E+} f_e²`
- **CWQ**: `Σ_{e∈E+} f_e² / c_e`
- **SU**: `Σ_{e∈E+} (f_e / c_e)²`
- **LCRQ**: `Σ_{(i,j)∈E+} f_ij² / p_ij`、ただし `p_ij = c_ij / Σ_{(i,k)∈E+} c_ik`

`E+` は正の有限容量のエッジ集合。容量ゼロのエッジの流量はゼロ。終端比率 `p_i = f_(i,t)/F*`、ただし `F*=0` では分布は未定義（画面上は「生成なし」を表示）。

**重要なUI上の条件**：同じ容量で4手法を切り替えても `F*` は変化しない。スライダーで容量を変更した場合は `F*` が変わることがある。線幅は**容量ではなく計算流量**を表す。容量変更量は別の色・数値で示す。

## Inverse

入力：基準ネットワーク、容量 `c_e`、固定した**人工的な観測分布** `q_i`。出力：容量 `c'_e` と終端分布が `q_i` に等しい最大フロー解。

目的：

`min_{c',f} Σ_{e∈E_bio} ((c'_e-c_e)/max(c_e,ε))²`

制約：

- `0 ≤ f_e ≤ c'_e`（容量が固定された補助エッジでは `c'_e=c_e`）
- 内部ノードで流量保存
- `f_(i,t) = F q_i`
- `c'_e ≥ 0`
- ベースラインの最小カット容量の不変性と、ベースライン最大流量以上の実行可能流量の確保

**今回の教材ネットワーク固有の設定**：人工的なソースから出る唯一の固定容量エッジを120とする。このカットが最小カットであるため、基準最大流量と補正後最大流量が120に固定される。論文の最小カット制約を一般化して実装したわけではない。

人工観測 `q=(A:25%, B:20%, C:55%)` を用いる。Cに流入する唯一のE13は基準容量58なので、120×55%=66を流すには、必ず容量が8以上増加する必要がある。E13だけを58→66に増やせば目標分布を実現できるため、変更量の二乗和の下限を達成する**大域最適解**がこの例では証明できる。

**重要**：Inverseが得た `f` が人工観測分布を再現するのであり、その`c'`に対して Forward の UQ/CWQ/SU/LCRQ をあらためて解いた場合の終端分布が `q` と一致する保証はない。

## ソルバー・検証

このPython検証は SciPy SLSQP を主に使用し、Forwardで一部の境界条件に遭遇したら `trust-constr` にフォールバックする。研究コードにある CVXPY/OSQP/CLARABEL との**独立実装による数値差検証はまだ実施していない**。

Web版ではブラウザ上で計算するか、独立した計算サービスを利用するかを判断する必要がある。GitHub Pages自体は静的ホスティングであるため、Pythonの数理ソルバーをそのまま実行することはできない。
